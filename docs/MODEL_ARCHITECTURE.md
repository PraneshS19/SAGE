# 0.1.3 processing changes

Direct and hierarchical planning still use effective provider context and output budgets. Intermediate outputs that exceed their byte or token limit can now be replaced with deterministic original excerpts. Each excerpt includes the original passage ID and exact text. Candidates are scoped to the failed step's selected passages, ranked with simple query-term and numeric signals, and packed inside the existing byte ceiling. Recovery is disclosed before consent and adds no model call. The excerpt set is selective and neither a complete fact index nor a semantic verifier. Provider errors still stop at the failed step. Final truncation preserves partial output and fails completion.

The final synthesis sees scoped source excerpts where they fit. It no longer receives a pooled minimum or maximum across all sources. Literal extrema can be inspected separately in the UI, with scope limitations. Claim-local reference checks avoid accepting a number merely because another sentence cited it. Optional restart storage is off by default and stores one bounded credential-free checkpoint. Restore does not dispatch inference. The existing versioned settings and history schemas accept older records.

# Model and provider architecture

SAGE plans from the selected model's configured context and capability metadata. The engine has no model-name or family branches. New installations start without a selected model. Existing v1 settings, keys and history retain their format, with optional profiles keyed by provider, endpoint and exact model ID.

In **Settings → AI Providers**, choose or enter the provider's exact model ID. Enter the effective serving context. Use **Advanced inference and model capabilities → Discover selected model capabilities** to request metadata from that endpoint, then save. Discovery sends the model ID or requests the model list. It sends no source data and starts no inference. Ollama discovery reads `/api/show` for advertised capacity and `/api/ps` for the currently loaded context when available. OpenRouter discovery reads `/models` metadata. OpenAI-compatible servers that do not publish these fields use the configured values and report unknown capabilities.

The planner caps the configured context at the advertised capacity when available. The observed runtime allocation is shown separately because Ollama requests `num_ctx` explicitly and may load a different context on the next call. A remote compatible endpoint's effective runtime must be confirmed by its operator. Clearing incorrect advertised metadata leaves the configured context in control. Token estimates use UTF-8 bytes per token with a configurable safety reserve. SAGE does not measure the exact server tokenizer or verify all server-side truncation behavior.

Response, note and safety budgets scale with effective context and accept per-model overrides. The request count, timeout and token estimate are configurable product resource policies. The planner tries one request before proposing a reviewed hierarchical plan. It budgets prompts, previous messages, output, safety margin and worst-case serialized notes. Larger windows can fit more source passages per request. Plans preserve original passage IDs, map coverage and the existing checkpoint retry workflow. The reviewed plan may omit the full numerical excerpt ledger if it cannot fit the final request. The source map coverage remains separately visible.

Ollama and compatible chat adapters handle native NDJSON, SSE and non-streaming JSON. OpenRouter uses its own reasoning parameter shape. Optional settings are sent only when supported by discovery, native protocol or an explicit endpoint override. An endpoint rejection produces an actionable error without an implicit retry. Choose `max_completion_tokens` in Advanced inference if the compatible endpoint requires it. Explicit reasoning fields and recognized tagged reasoning are kept out of answer text. Native thinking and opaque reasoning details are stored with continuation state and replayed only to the same provider, endpoint and model. SAGE does not execute tools.

A compatible GPT-OSS 120B endpoint can be configured through the same UI, with its runtime context and supported output and reasoning settings. The 4K/32K/128K acceptance cases use simulated capability profiles. GPT-OSS 120B itself was unavailable for live verification.
